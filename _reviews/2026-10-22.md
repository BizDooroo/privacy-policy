## 문서 수정으로 해결되지 않은 사항

### 알라딘램프: TLS 인증서 검증 우회 — 앱 수정 필요

`lamp_app/lib/utils/fetch.dart`의 `HttpClient.badCertificateCallback`이 모든 인증서 오류에 `true`를 반환한다. 검색어·도서 조회 요청은 HTTPS URL을 사용하지만 서버 인증서 검증을 우회하므로, HTTPS 표기만으로 안전한 전송을 보장할 수 없다. 이 콜백 제거와 정상 인증서/잘못된 인증서에 대한 요청 검증이 필요하다. 이번 작업은 문서 저장소만 수정하므로 앱 코드는 변경하지 않았다.

### 알라딘램프: 내장 정책과 실제 국외 이전 설정 — 제출 전 확인 필요

앱 내부 `lamp_app/lib/tabs/settings/components/privacy_policy.dart`는 이전 정책을 별도 문자열로 포함한다. 이번 웹 문서 변경은 해당 화면에 자동 반영되지 않는다. 공개 정책과 앱 화면의 정책을 일치시켜야 한다.

Sentry는 일반 실행과 백그라운드 실행 모두 이용자가 진단 설정을 켠 경우 초기화된다. 현재 코드에는 스토어 빌드에서 Sentry를 일괄 제거하는 조건이 없다. 사용하지 않으려면 제출 빌드에서 실제 초기화·전송 경로가 제거되었는지 확인해야 한다.

현재 DSN은 미국 리전의 기존 수집 주소를 사용한다. 프로젝트의 실제 리전, 요금제, 데이터 유형별 보관 기간, IP 제거 설정, 하위 처리업체 및 계약상 이전 근거는 저장소나 현재 제공된 연결 도구에서 확인되지 않았다. 공개 문서의 요금제별 기본 보관 기간은 실제 계정 설정 확인을 대신하지 않는다. 정책에는 이 한계를 명시했으며, 이 상태를 국외 이전 고지 요건 충족 확인으로 간주하지 않는다.

설정 화면에는 진단 토글과 짧은 용도 설명이 있다. 이것만으로 개인정보 보호법상 국외 이전의 별도 동의나 다른 적법 근거가 충족된다고 단정할 수 없다. Sentry를 유지하는 경우 적용 근거와 필요한 고지·동의 내용을 운영자가 확정하고 실제 화면·계약과 일치시켜야 한다.

로컬 실행 로그에는 검색어·도서 식별자를 포함한 요청 URL이 남을 수 있고, 데이터 초기화는 이 로그와 설정을 모두 삭제하지 않는다. 정책에 실제 범위를 반영했으며, 로그 최소화·보관 기간 제한은 별도의 앱 개선 사항이다.

### 위험한 출근길: Sentry의 빌드 조건 — 최종 산출물 확인 필요

코드는 릴리스 모드이면서 `SENTRY_DSN`이 있을 때만 오류 보고를 시작한다. 기본값은 빈 문자열이며 확인한 Android/iOS build.env에 DSN 주입은 없었다. `docs/release.md` 역시 Sentry 프로젝트·DSN 미설정 상태를 기록한다. 따라서 정책은 **현재 기본 배포 설정에서 외부 오류 보고 비활성**으로 한정했다. 외부 빌드 환경이나 실제 스토어 제출 파일을 검사한 결과는 아니다.

DSN이 주입된 산출물을 제출한다면 현재 비활성 설명을 그대로 사용할 수 없다. 코드상 오류·스택, 앱·기기·OS 상태와 SDK 설치 식별자 등 진단 정보가 전송될 수 있다. Dart 이벤트의 `user` 제거가 네이티브 크래시 전체의 식별자 제거를 보장하지 않는다. 이 경우 전송 항목·보관·처리위탁·국외 이전과 콘솔 신고를 함께 보완해야 한다.

### 공통 운영 확인

- 앱 내부에서 공개 정책에 쉽게 접근할 수 있는지와 실제 제출 버전의 Google Play Data safety / Apple App Privacy 신고를 대조해야 한다. 이번 변경은 앱 화면이나 콘솔을 수정하지 않는다.
- 문의 이메일의 1년 보관·삭제와 권리 요청 응대는 실제 운영에서 이행해야 한다. 농지대장·알라딘램프에도 다른 앱의 기존 문의 보관 기준인 1년을 명시했다. 메일함 설정·실제 삭제 여부는 검증하지 않았다.
- 기존 연락처가 앱마다 다르다. 문서상 주소를 보존했으며 수신 가능 여부나 담당자의 관리 권한은 이메일을 발송해 확인하지 않았다.
- 알라딘램프의 14세 미만 비대상 설명은 기존 정책을 유지했다. 실제 스토어 타깃 연령과의 일치는 별도 확인 사항이다.
