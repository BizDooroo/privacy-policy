# 개인정보 처리방침 검토 기록 — 2026-11-01 (빛말)

## 결과와 근거 범위

빛말(`textled`) 한·영 처리방침을 새로 작성했다. 이 기록은 운영자용이며 처리방침 본문이 아니다.

근거는 textled 저장소의 같은 날 작업 트리다. 주요 파일은 `lib/storage/settings.dart`, `lib/storage/library.dart`(기기 저장 항목), `lib/storage/app_storage.dart`·`web_backend.dart`(저장 위치), `lib/platform/`(화면 켜짐·밝기·URL 열기), `docs/decisions.md` D26(웹 전용 글꼴 대체)이다.

## 반영한 내용

- 저장 항목: 문구와 꾸밈 설정, 즐겨찾기(이름·순서)와 최근 50개(마지막 사용 시각), 언어·테마·표시 기본값·잠금 해제 방식·확인한 안전 안내. 서버 전송 없음.
- 저장 위치를 대상별로 적었다: 휴대폰·태블릿 앱 저장소, 데스크톱 앱 데이터 폴더(Linux 예시), 웹은 브라우저 localStorage와 그 삭제 방법.
- 권한 요청 없음, 광고·분석·오류 보고 SDK 없음. 화면 켜짐·밝기 조절은 기기 안에서만 동작하고 표시 종료 시 복원.
- 웹 버전만 번들 글꼴에 없는 글자를 표시할 때 `fonts.gstatic.com`에서 글꼴 파일을 받을 수 있음(D26). Google은 접속 정보를 받고 입력 문구는 받지 않음. 앱(모바일·데스크톱)은 글꼴을 내려받지 않음.
- 문의 처리·권리 행사는 초집중타이머 방침의 문구를 쓰되 개정 방침용 "기존 방침에 따라"는 뺐다. 운영자·보호책임자는 같고, 문의 이메일은 소유자 결정으로 회사 주소 `bizdooroo@gmail.com`(비밀투표·두런두런과 동일)을 쓴다.
- 웹 글꼴 대체는 이용자 브라우저가 Google에 직접 접속하는 것이지만, PIPA 국외 이전 해석 여지를 고려해 받는 자·항목·국가·시점·거부 방법을 표로 적었다.
- 밝기 복원은 표시 종료·앱 이탈 시 이루어지고 비정상 종료 시 즉시 복원되지 않을 수 있음을 적었다(iOS는 시스템 밝기를 바꿈).
- 데스크톱 저장 위치를 Windows·macOS·Linux 모두 적고, 손상 파일 사본(`.bak`)을 언급했다.
- 이용 시 유의사항: 표시 문구의 개인정보 노출 주의, 운전 중 사용·차량 부착 금지.
- 앱 내 링크: 설정 → 개인정보 처리방침이 언어별 페이지(`textled`, `textled_en`)를 브라우저로 연다.

## 확인이 필요한 사항

- 글꼴·문구 팩 내려받기(jsDelivr·GitHub·원 배포처가 IP를 받음)와 QR·링크 공유(카메라 권한, 링크 조각 데이터)는 아직 출시 전이다. 해당 기능을 내보내기 전에 방침을 개정하고 7일 전 안내 규정을 지킨다(textled `todo/packs-assets-repo.md`, `todo/sharing.md`).
- 웹 버전 호스팅 위치가 정해지면 제3조의 "웹 서버" 문장을 구체화한다.

## 개정 — 2026-11-01 (글꼴 팩 내려받기, 시행 2026-11-08)

근거: textled `docs/decisions.md` D34, `docs/spec/resource-packs.md` §6·§8, `lib/packs/`(요청 헤더는 `Accept`만, 쿠키·식별자 없음, 웹은 `credentials: omit`·`no-referrer`), 업스트림 호스트는 `fonts/manifest.json`의 단일 파일 URL에서 확인(`github.com`, `raw.githubusercontent.com`; zip 출처 글꼴은 jsDelivr 전용, D23).

- 제2조: 내려받은 글꼴 팩(글꼴·라이선스·설치 정보)을 저장 항목에 추가, 저장 위치(`packs` 폴더, 웹은 IndexedDB).
- 제3조: “받기”를 누를 때만 jsDelivr에서 받고 실패 시 일부만 GitHub에서 한 번 더 받음. 받는 자·항목·국가·시점·보관·거부를 웹 글꼴 대체와 같은 표 형식으로 적음. 카탈로그는 앱 내장이라 서버 조회 없음.
- 제4조: 팩 화면의 개별 삭제·모두 삭제.
- 제7조: 개정 공고 2026-11-01, 시행 2026-11-08(7일 전 안내). 앱 1.0이 아직 출시 전이라 실제 이용자 고지 부담은 없으나 규정대로 날짜를 둠.
- 남은 확인: 스토어 개인정보 양식(Apple 개인정보 라벨, Play 데이터 보안)에서 CDN 요청을 “수집”으로 볼지 제출 시 재확인(textled `store-release/submission-answers.md`).
- 리뷰 보완: `github.com/.../releases/download/...` 업스트림은 `release-assets.githubusercontent.com`으로 302 리다이렉트되므로(dart:io가 따라감) 받는 자 행에 GitHub 운영 호스트로 함께 적음.

## 개정 — 2026-11-02 (공유·QR 스캔·콘텐츠 팩, 시행 2026-11-09)

근거: textled `docs/decisions.md` D35·D36, `docs/spec/sharing.md` §1·§6·§7·§9, `lib/share/`, `lib/features/share/`(가져오기·스캔), `android/app/src/main/AndroidManifest.xml`(요청 권한은 `INTERNET`, `CAMERA`만), `ios/Runner/Info.plist`(`NSCameraUsageDescription`), Homepage `public/textled/s`(공유 링크 페이지, 외부 요청 없음).

- 제3조: 카메라는 “QR 스캔”을 누를 때 권한을 요청하고, 영상은 기기 안에서 QR을 읽는 데만 쓰며 저장·전송하지 않음. 이미지는 OS 선택 화면에서 고른 한 장만(사진 보관함 권한 없음).
- 제3조: 공유는 이용자가 직접 OS 공유 화면·클립보드로 보냄. 개발자는 받거나 보관하지 않음. 링크 데이터는 `#` 뒤(서버로 전송 안 됨), 미리보기 페이지는 저장·쿠키·분석 없음, AWS 웹 서버의 일반 접속 기록 가능. 공유받은 내용 속 주소에서 받아 오지 않음. 클립보드는 “붙여넣기”를 누를 때만 읽음.
- 제2·3·4조: S6에서 출시된 문구·배경·스타일 팩까지 “팩”으로 넓힘(같은 jsDelivr 경로, D35).
- 제6조: 공유한 문구의 책임은 공유한 사람에게 있음, 타인 권리 침해 금지.
- 제7조: 개정 공고 2026-11-02, 시행 2026-11-09(7일 전 안내). 미래 기능 약속 문장을 일반 문장으로 바꿈.
- 리뷰 보완(같은 날): 제3조에 AWS(S3·CloudFront) 전달과 국외 엣지 서버의 접속 정보 처리, 개발자가 접속 기록을 남기지 않음(CloudFront 로깅 미설정, Homepage `infra/site-stack.yaml`)을 적음. 제5조에 스타일 제출(GitHub 공개 이슈, 표시 이름만 팩에 실림, 요청 시 이후 팩에서 삭제)을 추가. 공유 링크 페이지는 2026-11-02에 배포되어 시행일 전부터 열리지만, 출시된 앱이 없어 링크를 만들 이용자가 아직 없다.
