# 개인정보 처리방침 검토 기록 — 2026-10-27

## 결과와 근거 범위

알라딘램프 한·영 처리방침의 제1·3·4·5·6·7·8조를 개정했다. 이 기록은 운영자용이며 처리방침 본문이 아니다.

근거는 aladin-lamp 저장소의 같은 날 작업 트리다. 주요 파일은 `lamp_app/lib/services/diagnostics/sentry_diagnostics.dart`, `services/settings/settings.dart`, `tabs/settings/settings_tab_page.dart`, `tabs/settings/components/privacy_policy.dart`이고, SDK는 sentry_flutter 9.30.1이다.

## 반영한 변경

- 설정 이름을 “진단 로그 보내기”에서 “오류 및 크래시 정보 서버 전송”으로 바꿨다. 켤 때는 보내는 정보와 보내지 않는 정보를 안내하는 동의 다이얼로그를 거친다.
- Sentry 프로젝트를 `gaerongsalon/aladin-lamp`(미국 리전)로 새로 만들어 DSN을 교체했다.
- release 빌드의 전송 범위를 줄였다.
  - `sendDefaultPii=false`로 두어 SDK가 `{{auto}}` IP를 넣지 않는다.
  - `beforeSend`에서 user, 기기 이름·id·고유 식별자·부팅 시각, 앱 `device_app_hash`, serverName을 제거한다.
  - `SanitizedAppException`이 아닌 예외의 메시지 원문을 제거하고, 문자열 속 URL의 query를 제거한다.
  - navigation breadcrumb의 arguments를 제거한다.
  - 세션 추적, 네이티브 크래시 처리, ANR, App Hang, 네이티브·print breadcrumb, 스크린샷·화면 구조, 리플레이를 끈다. 네이티브 이벤트는 Dart `beforeSend`를 거치지 않기 때문이다.
- debug 빌드(스토어 미배포, cata 내부 테스트)는 동의 없이 전송한다. 트레이스는 100%이고 FLog 로그도 Sentry Logs로 보낸다. 스크러빙 훅은 release와 같고 로그 본문의 URL query도 제거한다. 정책에도 이 내용을 명시했다.
- 앱 내장 처리방침을 웹 한국어판 본문과 일치시켰다. 2026-10-22 기록의 “내장 정책 불일치” 항목을 해소했다.

## 실측 검증

Linux 데스크톱 debug 엔진에서 실제 초기화 경로로 테스트 이벤트를 보냈다. 원문 표식 `SMOKESECRET`을 검색어·URL query·예외 메시지·route arguments에 넣었고, 다음을 확인했다.

- 이슈 2건, 트랜잭션·span 1건, 로그 2건이 수신되었고 어디에도 표식이 남지 않았다. 예외는 타입만 남았고, span·로그의 URL은 `?<redacted>` 처리되었다.
- user와 기기 이름·ID는 수신되지 않았다.
- 다만 Sentry 서버가 수신 IP로 `user.geo`(국가·도시)를 추정해 기록했다. 앱이 보내는 값이 아니므로 정책과 동의 문구에 “국가·도시 수준의 대략적 지역이 기록될 수 있음”을 추가했다.

## 확인이 필요한 사항

- **Sentry 프로젝트의 “Prevent Storing of IP Addresses” 설정.** 정책의 “IP 주소를 저장하지 않도록 설정” 문구가 사실이려면 이 설정이 켜져 있어야 한다. 연결 도구로는 변경할 수 없어 대시보드에서 수동으로 설정해야 한다. 설정은 Project Settings → Security & Privacy에 있다.
- 2026-10-22 기록의 TLS 인증서 검증 우회(`utils/fetch.dart`)는 여전히 남아 있다. 이번 변경은 Sentry 전송 경로만 다뤘다.
- 시행일(11/3) 전에 스토어 빌드를 배포하면 앱 내장 정책에 이미 개정 내용이 표시된다. 바뀌는 것은 수집 축소뿐이므로 이용자에게 불리한 변경은 아니다.
